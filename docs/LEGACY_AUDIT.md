# CineBase — аудит старой реализации

Дата: 25 октября 2026 года. Основание: просмотр исходников, миграций, конфигурации и дерева GitHub-репозитория. Приложение в рамках аудита не запускалось; работоспособность инфраструктуры не заявляется.

## Решение

Продолжить существующий репозиторий `Rokki-Khazratov/CineBase`, сохранив Git-историю и MIT LICENSE. Начать актуальную реализацию веб-каталога с чистой основы в том же репозитории.

Старый код — небольшой учебный инфраструктурный эксперимент. Объём уже реализованной продуктовой логики недостаточен, чтобы переносить его ограничения в новый каталог.

Старую tracked-заготовку заменяет документация нового проекта. Новые web/API модули создаются по фазам технического задания. Это изменение структуры и плана, а не готовая новая версия приложения.

## Проверенные находки

| Находка | Свидетельство в старом дереве | Решение |
| --- | --- | --- |
| Репозиторий существует и доступен для записи | GitHub: `Rokki-Khazratov/CineBase`, default branch `main` | Продолжить этот репозиторий |
| Рабочих маршрутов каталога нет | `app/api/router.py` подключает только `health` и `cache` | Спроектировать публичный catalog API заново |
| Auth/CRUD и полный набор тестов заявлены без реализации | README и `docs/api-reference.md`; соответствующих маршрутов и tracked-тестов нет | Заменить документы точным текущим статусом |
| ORM и миграция описывают разные варианты схемы | Модели используют PostgreSQL UUID/ARRAY/JSON, начальная миграция — SQLite String/Text | Одна схема PostgreSQL и проверяемые миграции |
| Local default и Compose расходятся | В локальной конфигурации SQLite, в Compose PostgreSQL | Единый тип БД в разработке и тестах |
| Кеш-операции подключены без проверки доступа | `POST /cache/clear`, `GET /cache/keys`, `GET /cache/stats` | Удалить экспериментальные публичные маршруты |
| Makefile содержит команды для отсутствующих частей | Ссылка на `app.services.auth_service`, отсутствующий production Dockerfile, отсутствующий extra `dev` в pyproject | Вносить команды только с работающей реализацией |
| Дублируется форматирование и есть старые pins | Ruff + Black + isort; зависимости зафиксированы на старых версиях | Выбрать один согласованный набор инструментов и lockfiles в фазе 2 |
| Веб-приложения нет | Отсутствуют frontend manifest и UI исходники | Начать UX-прототип в фазе 1 |
| Предел года устаревает | Ограничение `year <= 2030` | Хранить объявленные будущие даты без такого фиксированного потолка |

## Что полезно сохранить как идеи

- Выделение конфигурации, логирования, API-маршрутов и работы с БД.
- Внутренний ID фильма отдельно от внешнего ID поставщика.
- Явная модель получения метаданных и локальных переопределений при необходимости.
- Health-check и автоматические миграции как часть воспроизводимого запуска.

Реализация этих идей будет согласована с новым scope; старые файлы сами по себе не считаются завершёнными задачами.
